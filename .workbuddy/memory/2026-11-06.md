## 项目分析（只读，未改动代码）

- 定位：Windows 本地工作活动记录工具。watchdog 文件事件 / 前台窗口轮询 / 键鼠钩子 → EventProcessor → DatabaseWriter 单 SQLite 连接 → ReportGenerator 生成 Markdown 日报，tkinter GUI + pystray 托盘。
- 实测：`python -m unittest discover -s tests -v` 57 项全通过（3.06s）；git 工作区有 10 个已修改 + 4 个未跟踪文件（parsing.py、3 个测试文件），当前版本未提交。
- 关键结论（已用只读脚本实证）：
  1. `report.py:73-75` 文件夹操作在 `FILE_ACTIONS` 判断之前被追加到 `file_logs`/`projects`，导致"操作记录/涉及文件"虚高、详细日报把文件夹列成文件。
  2. `browser.py` 的 `PageTracker.flush` 用会话结束时刻作 `timestamp`，跨天停留归属到次日（实证 23:58 开始 420s → 落库 00:05）。`ApplicationTracker` 同构。
  3. `event_processor._handle_modified` 未建立 FileState 且 snapshot 初值时连续 MODIFIED 零记录；CREATED/锁文件不同步 `_snapshots`，且 MODIFIED 无防抖。
  4. 三个时间基准混用（`occurred_at` / `datetime.now()` / `time.monotonic()`），时钟回拨会误判重复。
  5. `_file_size` 线程内 sleep 最长 1s + `_process_opening_file` 全进程 `open_files()` 扫描，配合无界队列和永不清理的 `_debounce`/`_paths` 是积压/OOM 风险。
  6. 隐私：`LogFile/app.log` 明文含页面标题与完整路径；`msedgewebview2.exe` 在浏览器白名单；关闭窗口仅 `withdraw`，监控线程继续运行。
  7. 构建：`build.ps1` 未切换工作目录，`.spec` 未显式打包 Tcl/Tk，`upx=True` + 未签名；`dist/`、`smoke_test/`、`LogFile/` 有真实明文记录与孤儿 WAL/SHM。
- 修复优先级：统一时钟 + MODIFIED 防抖/快照 → 单线程去阻塞 + 队列有界 → 报告聚合口径与跨天归属 → 隐私与文档 → 关闭竞态与构建。

## 全量修复（同日完成，用户要求"全部修复"）

- 数据正确性：`browser.py` 抽 `SessionTracker` 基类，时长用 monotonic、落库用会话开始时刻、跨天按天拆分（drain_events 承载额外事件）；`report.py` 文件夹操作单独分组、以 `file_path` 聚合；`event_processor.py` 所有时间差改用 monotonic、固定窗口防抖、CREATED/锁文件/原子保存同步 `_snapshots`、MODIFIED 不依赖编辑器白名单也会记 SAVE；`database.py` 兼容 ISO/旧时间戳并逐行跳过坏行。
- 稳定性：两个队列设 `queue_max_size`（默认 10000）+ 满时丢弃计数告警；`_prune_state` TTL/容量上限；`_file_size` 不再 sleep；`_opening_process` 结果缓存；destructive 事件按到达时间分批 flush、目录操作 2 个窗口后过期；`DatabaseWriter` 用 `_stop_requested` flag + drain 保证停止不丢数据、`_safe_flush` 捕获 Exception 并重试 5 次；`_submit_log` 丢弃改 WARNING。
- 幂等：`InputActivityCounter.snapshot()` 只提交增量，`generate_report` 仅当天调用；历史日报不触碰实时计数器。
- 隐私：日志默认 INFO（DEBUG 不落盘）、事件/会话详情改 DEBUG 且不含标题与路径；`msedgewebview2.exe` 移出 BROWSERS；关闭窗口改为提示 + 隐藏到托盘；README 补充完整隐私与运行行为说明。
